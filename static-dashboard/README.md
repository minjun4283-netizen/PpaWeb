# PPA 계약관리 — 정적 HTML 대시보드 (임시 · 서버 불필요)

`backend`/`frontend`의 편집 가능한 웹앱을 올릴 사내망 서버가 아직 없는 동안,
**서버 없이 지금 바로 쓸 수 있는 조회 전용 대시보드**입니다. 사내에서 이미
검증된 패턴(정산 대시보드: `ppa_core.py`/`ppa_pipeline.py`/`dashboard_render.py`)을
그대로 따랐습니다 — 데이터를 JSON으로 HTML 안에 통째로 넣고 JS로 처리하는
단일 파일. **외부 CDN·폰트·라이브러리를 하나도 쓰지 않아** 인터넷이 안 되는
VDI에서도 그대로 열리고, 만들어진 HTML 파일 하나만 공유폴더·메일·Teams로
보내면 누구나 브라우저로 바로 봅니다.

## ⚠️ `dashboard_recreate.bat`으로 만든 HTML 파일은 조회 전용입니다

`build_dashboard.py`/`dashboard_recreate.bat`으로 만든 `PPA현황.html`은 그
자체로는 값을 고쳐서 저장하는 기능이 없습니다 — 서버가 없는 순수 HTML
파일이라 팀원들에게 메일/Teams로 보내서 보는 용도입니다. 이 경우 **데이터
수정은 계속 엑셀에서** 하고, 최신 상태를 보여주고 싶을 때 배치파일을 다시
실행해 HTML을 새로 만들면 됩니다.

**입력까지 브라우저에서 하고 싶다면** 아래 "실시간 입력 서버" 절을 보세요 —
서버 하나를 띄우는 대신, 저장을 누르면 실제로 엑셀에 반영됩니다.

## 실시간 입력 서버 — 브라우저에서 입력하면 엑셀에 바로 반영 (선택 기능)

`ppa_liveserver.py`를 실행하면(더블클릭용 `run_live_server.bat` 제공) 계속
떠 있는 작은 웹 서버가 뜨고, 대시보드 화면 오른쪽 아래에 **"간편 입력/저장"**
버튼이 나타납니다. 표를 고르고 값을 입력해 저장을 누르면:

1. `excel_com.py`가 **Windows COM으로 엑셀 프로그램 자체를 직접 조작**해서
   그 값을 씁니다 — 파일을 열어 덮어쓰는 게 아니라, 진짜 엑셀이 하는 것과
   똑같은 방식입니다. 그래서 openpyxl이 못 여는 예전 바이너리(CFB) 포맷
   xlsm에도 그대로 동작합니다.
2. **그 순간 엑셀 파일이 열려 있으면 그 세션에 바로 씁니다** — 화면의 셀이
   바로 바뀝니다. 저장을 먼저 요구하지 않고, 지금 화면(메모리) 상태를
   그대로 읽어갑니다. 열려 있지 않으면 보이지 않는 새 엑셀 인스턴스를 띄워
   열고 저장한 뒤 그 인스턴스만 조용히 닫습니다(사용자가 나중에 여는 세션과는
   무관).
3. 저장 전에 PK 공란·FK 참조(존재하지 않는 발전소ID 등)를 확인해서, 문제가
   있으면 엑셀에 쓰지 않고 오류를 먼저 보여줍니다(빈 필수값은 화면에서
   입력하는 동안에도 바로 빨간 테두리로 표시됩니다).
4. 저장이 끝나면 서버가 바로 다시 읽어 `PPA현황.html`을 갱신하고 화면도
   새로고침됩니다 — 별도로 "대시보드 생성"을 다시 누를 필요가 없습니다.

### 삭제 — 참조 무결성 검사가 있는 안전한 삭제

"불러오기"로 기존 데이터를 불러온 상태에서만 **삭제** 버튼이 활성화됩니다
(새 입력 중에는 지울 대상이 없으므로 비활성).

1. 삭제를 누르면 먼저 **다른 표에서 이 PK를 참조하고 있는지** 확인합니다
   (`/api/references`) — 예를 들어 발전소를 지우려는데 그 발전소를 쓰는
   구매계약이 남아있으면, 몇 건이 어느 표에서 참조 중인지 보여주고
   **삭제 버튼 자체를 비활성화**합니다. 참조하는 데이터를 먼저 정리해야만
   지울 수 있습니다 — 실수로 연쇄 삭제되는 일은 없습니다.
2. 참조하는 데이터가 없으면 "되돌릴 수 없습니다, 정말 삭제하시겠습니까?"
   확인창이 뜨고, 확인해야 실제로 지워집니다.
3. 실제 삭제는 그 행을 엑셀에서 **완전히 삭제**(`Rows(n).Delete`)합니다 —
   표(ListObject) 안에 있어도 엑셀이 표 범위와 서식을 자동으로 줄여줍니다.
   이 시스템의 6개 표는 셀 수식을 쓰지 않는 순수 데이터 표라서(검증/파생값은
   전부 이 코드가 계산), 행 삭제로 인한 수식 참조 깨짐 걱정이 없습니다.
4. 삭제 직후 [변경] 탭에 "삭제된 항목"으로 자동 반영됩니다 — 별도 처리
   없이 기존 스냅샷 비교 로직을 그대로 씁니다.

### 컬럼별 검색으로 기존 데이터 찾기

"간편 입력/저장" 폼에서 기존 데이터를 불러올 때, 표가 큰 경우 PK를 하나하나
찾기 번거로우므로 **컬럼을 골라(또는 "전체 컬럼") 키워드로 검색**하는 상자를
뒀습니다. 검색어를 입력하는 즉시(별도 조회 버튼 없이) 그 표의 모든 컬럼 값을
훑어 일치하는 행을 목록으로 보여주고(최대 30건, 넘으면 "N건 더 있음" 안내),
아무 결과나 클릭하면 그 레코드가 바로 폼에 채워집니다. 표 전체 데이터는
`/api/records`로 한 번만 받아 화면에서 걸러내므로(서버 왕복 없이) 타이핑할
때마다 즉시 반응합니다.

### 그룹(마스터+자식) 일괄 입력·삭제

관련된 표를 하나씩 따로 저장하지 않고 **한 화면에서 한 번에** 처리하고 싶을
때 쓰는 기능입니다. 폼 위쪽의 "개별입력 / 그룹A / 그룹B" 중에서 고릅니다.

- **그룹A**: 발전소 1건 + 그 발전소의 구매계약 여러 건을 한 화면에서
- **그룹B**: 수요기업 1건 + 그 수요기업의 판매계약 여러 건, 그리고 **각
  판매계약 카드 안에** 그 판매계약의 전기사용지 여러 건까지(2단 중첩)

동작 방식:

1. 기존 마스터(발전소/수요기업)를 컬럼별 검색으로 불러오면, 딸린 자식(과
   손자) 데이터를 자동으로 함께 찾아와 각각 카드로 펼쳐줍니다. "새 OOO 입력"을
   누르면 빈 상태로 새로 시작합니다.
2. 자식/손자 카드는 "+ 추가" 버튼으로 새로 만들거나, 기존 카드에서 "삭제
   표시"를 눌러 저장 시 지워지도록 표시할 수 있습니다(신규로 추가했다가 마음이
   바뀐 카드는 "제거"로 그냥 목록에서 빼면 됩니다 — 아직 엑셀에 없으니 삭제
   확인이 필요 없습니다). 자식을 삭제 표시하면 그 자식에 딸린 손자도 함께
   삭제되도록 자동으로 표시됩니다(카드에 "하위 N건과 함께 삭제됩니다" 안내).
3. **일괄 저장**을 누르면 마스터+자식(+손자) 전체를 먼저 한꺼번에 검증하고
   (필수값 공란, FK 등), **하나라도 문제가 있으면 아무것도 엑셀에 쓰지 않고**
   문제 목록만 알려줍니다. 전부 통과해야 엑셀에 실제로 반영되며, 이때 저장은
   `wb.Save()` 한 번만 호출합니다(항목별로 저장을 여러 번 하지 않음) — 저장
   중간에 몇 건만 반영되고 나머지가 빠지는 일이 없습니다. 아직 저장 전인 새
   마스터를 참조하는 새 자식도(같은 배치 안이면) FK 오류 없이 함께 저장됩니다.
4. **그룹 전체 삭제** 버튼은 지금 불러온 마스터와 그 모든 자식·손자를 통째로
   지웁니다(별도 확인창 있음) — 개별 삭제와 달리, 이 배치 밖에서 다른 표가
   참조하고 있지 않은 한 마스터-자식 관계 자체는 배치 안에서 안전하게
   함께 지워집니다. 이 배치 **밖에서** 참조하는 데이터가 있으면(예: 수급매칭이
   참조하는 전기사용지) 그 항목만 오류로 걸리고 역시 아무것도 반영되지 않습니다.

### 값이 정해진 컬럼 — 자유 입력 대신 선택/자동 계산

일부 컬럼은 오타·형식 불일치를 막기 위해 자유 텍스트 대신 정해진 방식으로만
입력하도록 했습니다(개별입력/그룹 화면 모두 적용):

- **발전원**: `태양광` / `풍력` / `소수력` 중에서만 선택(드롭다운)
- **Readiness**: `New` / `Operating` 중에서만 선택(드롭다운)
- **MGA_Supply, MGA_Demand**: 예전에 `=n/24` 수식으로 관리되던 값입니다. 화면에는
  최종 소수값 대신 **n만 입력**하면 되고, 입력하는 즉시 `n / 24` 계산 결과가
  아래에 표시되며 그 계산값이 저장됩니다(예: `3.2` 입력 → `0.1333333333` 저장).
  기존 데이터를 불러오면 저장된 값에서 n을 역산해 다시 보여줍니다.
- 위 드롭다운에 없는 값이 이미 엑셀에 들어있는 기존 데이터를 불러오면, 조용히
  지우지 않고 "(목록에 없는 기존 값)"으로 표시된 임시 항목을 만들어 보존합니다
  — 저장하려면 정해진 값 중 하나로 바꿔야 합니다.

### 더 편해진 입력 흐름

- **불러온 레코드 표시**: 데이터를 불러오면 툴바에 어떤 레코드를 불러왔는지
  칩(초록 점 + 라벨)으로 보여주고, 옆의 ✕로 바로 선택을 해제할 수 있습니다.
- **복제해서 새로 입력**: 기존 레코드를 불러온 상태에서 누르면 PK만 비운 채
  나머지 값은 그대로 유지한 "새 입력" 상태로 바뀝니다 — 비슷한 계약을 여러
  건 연달아 입력할 때 유용합니다.
- **저장하지 않은 변경 내용 보호**: 값을 입력한 채로 창을 닫거나, 다른
  레코드를 불러오거나, 개별입력↔그룹A↔그룹B를 전환하려 하면 "계속하면
  사라집니다" 확인을 한 번 물어봅니다 — 실수로 입력 내용을 날리는 일을
  막습니다.
- **Enter로 저장**: 입력칸(검색 상자 제외)에서 Enter를 누르면 바로 저장
  버튼을 누른 것과 같이 동작합니다(여러 줄 입력칸에서는 줄바꿈이 우선).
- **검색창 자동 포커스**: 화면을 처음 열거나 표/모드를 바꾸면 컬럼별 검색
  상자에 커서가 자동으로 가 있어 바로 타이핑할 수 있습니다.
- **저장해도 보던 화면 그대로 유지**: 저장/삭제 후에는 최신 데이터를
  반영하려고 화면 전체를 다시 불러오는데, 예전에는 이때 항상 [홈] 탭으로
  돌아갔습니다. 지금은 저장하기 직전에 보고 있던 탭(예: 구매계약 목록,
  탐색 결과 등)을 기억해뒀다가 다시 불러온 뒤 그 화면으로 자동 복귀합니다
  (`#lookup=...` 딥링크로 접속한 경우는 그 링크가 우선합니다).

### "간편 입력/저장" 버튼 없이도 — 표/탭 안에서 바로 수정·추가·삭제

플로팅 폼을 열어 표를 고르지 않아도, **지금 보고 있는 화면에서 바로** 입력할
수 있습니다:

- 각 표 탭(발전소/구매계약/…)의 목록 위에 있는 **"+ 새 OOO 추가"** 버튼 —
  그 표를 선택한 채로 간편 입력 폼이 바로 열립니다.
- 아무 행이나 클릭하면 뜨는 **상세 모달**에 이제 **수정**/**삭제** 버튼이
  있습니다 — 클릭하면 그 레코드를 불러온 채로 간편 입력 폼이 열리고(삭제는
  바로 참조 무결성 확인 후 삭제 확인창까지 이어집니다), 검증·FK 확인 등은
  전부 기존 폼의 로직을 그대로 재사용합니다(따로 구현한 별도 경로가
  아닙니다 — 그래서 동작이 완전히 동일합니다).

실시간 입력 서버가 켜져 있지 않을 때(정적으로 생성된 HTML을 그냥 열어봤을
때) 이 버튼들을 누르면 "실시간 입력 서버 실행 중에만 사용할 수 있습니다"라는
안내만 뜨고 조용히 무시됩니다 — 오류가 아닙니다.

### 실행 방법 — 콘솔 창 없이 시작 (권장)

```
📁 (작업 폴더)\
   PPA파일.xlsm
   📁 static-dashboard\
      run_live_server_hidden.vbs    ← 콘솔 창 없이 백그라운드로 시작(권장)
      _run_server_hidden_worker.bat ← 위 vbs가 내부적으로만 씀(직접 실행 X)
      run_live_server.bat           ← 콘솔 창이 보이는 예전 방식(문제 진단용)
      ppa_liveserver.py, excel_com.py, dashboard_form.js
      dashboard_recreate.bat, build_dashboard.py, ppa_*.py, vendor\...
```

엑셀의 **[실시간 입력 서버 시작]** 버튼(`../vba-form/README_대시보드생성.md`
참고)이 이제 `run_live_server_hidden.vbs`를 통해 서버를 띄웁니다 — **정상적으로
시작되면 콘솔 창이든 안내창이든 아무것도 뜨지 않고, 몇 초 뒤 브라우저만
자동으로 열립니다.** 문제가 있을 때만(엑셀/python을 못 찾음, 서버가 30초 안에
응답하지 않음) 안내 창이 뜹니다. 서버의 출력은 화면 대신
`static-dashboard\live_server.log` 파일에 남습니다.

`run_live_server_hidden.vbs`를 직접 더블클릭해서 실행해도 되고(탐색기에서
`.vbs` 더블클릭은 기본적으로 wscript.exe로 실행되어 콘솔이 뜨지 않습니다),
`stop_live_server.bat`으로 끄는 방법은 그대로입니다(포트 번호로 찾아서
종료하므로 콘솔 창이 있든 없든 동일하게 동작합니다).

콘솔 창을 직접 보면서 진행 상황을 확인하고 싶거나(디버깅), 위 방법이 안 될 때는
예전처럼 콘솔이 보이는 `run_live_server.bat`을 더블클릭하세요 — 상위 폴더의
xlsm을 자동으로 찾아 `http://127.0.0.1:8842`에서 서버를 띄우고 브라우저를
자동으로 엽니다. 이 창을 닫으면 서버도 함께 종료됩니다.

**시작 속도**: 서버가 뜨자마자(엑셀 COM 연결/6개 표 읽기를 기다리지 않고)
바로 포트를 열고 브라우저를 띄우도록 바꿨습니다 — 그 사이 브라우저에는
"불러오는 중..." 안내 화면이 잠깐 보이다가 준비되는 즉시 자동으로 실제
대시보드로 바뀝니다. pywin32 설치 여부 확인도 별도로 python을 한 번 더
띄워서 하지 않고 `ppa_liveserver.py` 자신이 시작하자마자 바로 확인하도록
바꿔서, 그만큼 불필요한 대기가 줄었습니다.

### pywin32 설치 (필수)

이 기능은 openpyxl이 아니라 **Windows COM 자동화**를 쓰므로 `pywin32`가
반드시 있어야 합니다. openpyxl과 달리 컴파일된 패키지라 `vendor/`처럼
파일만 복사해 넣을 수 없습니다.

- **인터넷이 되는 VDI라면**: `python -m pip install pywin32`
  (또는 `..\python-embed\python.exe -m pip install pywin32` — embeddable
  배포본은 기본적으로 pip이 없으므로, 먼저 <https://bootstrap.pypa.io/get-pip.py>를
  같은 방식으로 받아 `python.exe get-pip.py`로 pip을 넣어야 합니다)
- **인터넷이 안 되는 VDI라면**: 인터넷 되는 PC에서
  `pip download pywin32 --no-deps -d ./pywin32_offline`으로 해당 VDI의 Python
  버전/아키텍처에 맞는 `.whl` 파일을 받아 옮긴 뒤,
  `python -m pip install --no-index --find-links=./pywin32_offline pywin32`
- 이 모듈은 `win32com.client.Dispatch`/`GetObject`(동적 바인딩)만 사용하므로
  pywin32 설치 후 흔히 필요한 `pywin32_postinstall.py -install`(레지스트리
  등록) 단계는 **필요 없습니다** — 패키지만 있으면 바로 동작합니다.
- pywin32가 없으면 `run_live_server.bat`이 서버를 띄우기 전에 바로 감지해서
  안내하고 멈춥니다(조용히 실패하지 않습니다).

### 동시 접근/충돌에 대해 알아둘 것

- 저장은 **서버 안의 전용 스레드 하나가 순서대로 처리**합니다 — 두 사람이
  동시에 저장 버튼을 눌러도 한 번에 하나씩만 엑셀에 반영되고, 같은 행을
  두고 덮어쓰는 경합은 나지 않습니다.
- 하지만 **사용자가 엑셀에서 같은 셀을 직접 타이핑하고 있는 도중**에
  브라우저 쪽 저장이 들어오면, 화면의 셀 값이 사용자 모르게 바뀔 수
  있습니다 — 지금 열려 있는 세션에 바로 쓰는 방식을 택했기 때문에 생기는
  당연한 트레이드오프입니다(파일을 닫아야만 저장되게 하는 더 안전하지만
  불편한 대안도 있습니다 — 필요하면 말씀해주세요).
- 표(ListObject)가 있는 시트는 새 행을 추가할 때 표를 확장해서(서식·필터
  유지) 넣고, 없으면 마지막 사용 행 바로 다음에 씁니다.
- `dashboard_recreate.bat`(서버 없음, openpyxl 기반)과 이 서버(COM 기반)는
  같은 `PPA현황.html`/`PPA현황_snapshot.json`을 공유합니다 — 어느 쪽으로
  갱신하든 [변경] 탭 누적 비교는 그대로 이어집니다.

### "같은 이름의 통합 문서가 이미 열려 있습니다" 류의 엑셀 오류가 뜬다면

이미 그 파일이 열려 있는데도 서버가 그걸 못 찾고 **새로 하나 더 열려다가**
나는 오류입니다(엑셀은 같은 이름의 파일을 두 번 동시에 열 수 없어서 이때
"파일 이름이나 경로가 없습니다 / 다른 프로그램에서 사용 중입니다 / 이미
열려 있는 통합 문서와 이름이 같습니다"라는 안내를 냅니다). 엑셀 프로세스가
여러 개 떠 있거나(워크북마다 별도 창), OneDrive 경로 표기 차이 때문에
"이미 열려 있음"을 놓치면 생길 수 있던 문제라 파일 경로로 직접 찾는 방식
(`GetObject(파일경로)`)으로 바꿔뒀습니다 — 그래도 이 오류가 다시 나면
캡처해서 보내주세요(어느 단계인지 원본 오류까지 같이 보이도록 고쳐뒀습니다).

### 아무도 안 쓰는데 계속 "읽기 전용"으로 열린다면

서버가 그 파일을 열어줄 엑셀을 못 찾으면(아무 데도 열려 있지 않을 때)
**보이지 않는 새 엑셀을 자기가 하나 띄워서** 대신 열어줍니다. 예전에는
이 숨김 인스턴스를 서버가 켜져 있는 내내 붙잡고 있어서, 서버 콘솔 창이
비정상적으로 닫히면(강제 종료 등) 그 숨김 인스턴스가 백그라운드에 남아
파일을 계속 잠가버릴 수 있었습니다 — **화면엔 아무것도 안 보이는데 파일은
계속 "사용 중"** 인 것처럼 보이는 원인입니다. 지금은 요청 하나가 끝날
때마다 우리가 띄운 숨김 인스턴스를 바로 닫도록 고쳤고, 콘솔 창을 X로
닫는 경우도 별도로 감지해서 정리합니다.

**지금 이미 막혀 있는 상태라면:**

1. `static-dashboard\stop_live_server.bat`을 실행하세요 — 8842 포트에서
   떠 있는 서버를 찾아 정상 종료(안 되면 강제 종료)합니다.
2. 그래도 안 풀리면, **작업 관리자 → 자세히 탭**에서 화면에는 안 보이는
   `EXCEL.EXE` 프로세스가 남아있는지 확인하고 종료하세요(진짜 쓰고 있는
   엑셀 창까지 실수로 끄지 않도록, 작업 저장 여부를 먼저 확인해주세요).
3. 그래도 "읽기 전용"이면 파일과 같은 폴더에 `~$파일명.xlsm` 처럼 `~$`로
   시작하는 잠금 파일이 남아있는지 확인하고(아무 프로세스도 안 쓰고 있는
   게 확실할 때만) 지우세요.

같은 이유로, 우리가 새로 띄운 숨김 인스턴스가 **사용자의 다른 애드인**
(OpenSolver.xlam 등, 평소 엑셀을 켤 때 자동으로 같이 열리는 것들)까지
잠가버리는 문제도 있었습니다. 지금은 우리 파일을 열기 전에 그렇게 자동으로
딸려온 애드인을 전부 먼저 닫도록 고쳤습니다 — 그래도 `OpenSolver.xlam` 등이
"편집 중"으로 잠겨 있다면 위 1~3번과 같은 방법으로 정리해주세요.

### 경로에 `&`가 들어 있으면(예: `... - SKI E&S\...`) 배치파일이 깨졌었습니다

`.bat` 파일 안에서 `&`는 "명령 구분자"로 특별 취급됩니다. 폴더 경로를
화면에 그대로 찍어주는(`echo`) 줄에서 그 경로를 따옴표 없이 썼더니, 경로에
`&`가 있으면 거기서 잘려 "'S'은(는) 내부 또는 외부 명령이 아닙니다" 같은
오류로 죽어버렸습니다(실제 배치파일 실행 자체가 시작도 못 하고 멈춤). 지금은
경로를 표시/사용하는 곳을 전부 따옴표로 감싸도록 고쳤습니다 — 콘솔에 경로가
큰따옴표로 둘러싸여 나오는 건 정상입니다.

### 확인된 범위 / 먼저 봐주실 것

이 환경에는 Windows/Excel이 없어 COM 호출을 실제로 실행해보지 못했습니다
(문법·모듈 구조·pywin32 없을 때의 오류 메시지까지만 검증). 사본에서 아래
순서로 확인해주세요.

1. pywin32 설치 후 `run_live_server.bat` 실행 → 콘솔에 `[OK] 서버 시작` 이
   뜨고 브라우저가 자동으로 열리는지
2. 엑셀에서 그 xlsm을 열어둔 채로 브라우저에서 값을 입력해 저장 → 엑셀
   화면의 셀이 저장을 누르는 즉시 바뀌는지, `wb.Save()`가 실제로 파일에도
   반영되는지(제목표시줄에 "저장되지 않음" 표시가 안 남는지)
3. 엑셀을 완전히 닫은 상태에서 저장 → 새 셀 값이 들어가고, 작업 관리자에
   여분의 EXCEL.EXE 프로세스가 남지 않는지(우리가 띄운 인스턴스가 제대로
   종료되는지)
4. 존재하지 않는 발전소ID로 구매계약을 저장 시도 → 엑셀에 쓰지 않고 오류
   메시지가 먼저 뜨는지
5. 새 PK로 저장(추가) → 표(ListObject) 서식이 새 행까지 그대로 이어지는지
6. 저장 직후 대시보드 화면이 자동으로 새로고침되고 [변경] 탭에 방금 저장한
   항목이 뜨는지
7. 엑셀 쪽 버튼(`../vba-form/README_대시보드생성.md`의 [실시간 입력 서버
   시작])으로도 같은 서버가 뜨는지
8. 참조되고 있는 데이터(예: 구매계약이 딸린 발전소) 삭제 시도 → 삭제 버튼을
   눌러도 확인창에서 참조 목록만 보이고 실제 삭제 버튼은 비활성인지
9. 아무도 참조하지 않는 데이터 삭제 → 확인 후 실제로 엑셀 행이 지워지고
   (표 서식이 남은 행까지 자연스럽게 줄어드는지), [변경] 탭에 "삭제된
   항목"으로 뜨는지
10. 필수 필드를 비운 채 다른 곳을 클릭(blur) → 그 필드가 빨간 테두리로
    바로 표시되는지, 저장 시도 시 토스트 알림으로 오류가 뜨는지(자바스크립트
    오류 없이)
11. 이미 존재하는 PK로 "새 입력" 상태에서 값을 입력 → "이미 존재합니다"
    안내 문구가 뜨는지(저장을 막지는 않음 — 저장하면 수정으로 처리)
12. 컬럼별 검색 상자에 키워드 입력 → 타이핑하는 즉시 결과가 좁혀지는지,
    "전체 컬럼"과 특정 컬럼을 바꿔가며 검색 범위가 실제로 달라지는지
13. 그룹A에서 기존 발전소를 불러와 새 구매계약을 추가 후 일괄 저장 →
    발전소는 그대로, 구매계약만 새로 추가되는지, [변경] 탭에 새 구매계약이
    "추가"로 잡히는지
14. 그룹B에서 기존 판매계약을 "삭제 표시" → 그 안의 전기사용지도 자동으로
    함께 삭제 표시되는지(안내 문구 확인), 일괄 저장 후 둘 다 실제로 지워지는지
15. 그룹A에서 마스터 필수값을 비운 채 일괄 저장 시도 → 엑셀에 아무것도
    반영되지 않고(자식도 포함) 오류 안내만 뜨는지
16. 대시보드를 여러 번 다시 만든 뒤 [변경] 탭의 "전체 변경 이력"에서 검색어/
    구분(추가·수정·삭제)/표로 좁혀지는지, 이전 생성분의 항목도 계속 남아있는지
    (최대 1,000건까지 누적, 넘으면 오래된 것부터 자동으로 빠짐)
17. 저장을 여러 번 반복해도 [변경] 탭의 "기준점 대비" 표시가 매번 초기화되지
    않고 계속 쌓이는지 → **변경 비교 기준 리셋** 버튼을 누른 뒤에만 초기화되는지,
    리셋해도 "전체 변경 이력"은 그대로 남아있는지
18. 발전원/Readiness가 드롭다운(자유 입력 불가)으로 뜨는지, 목록에 없는 예전

    저장 후 다시 불러오면 n이 올바르게 역산되어 표시되는지
20. 기존 데이터를 불러온 채로 값을 고치고 창을 닫거나 다른 레코드를 불러오려
    하면 확인창이 뜨는지, 취소하면 그대로 남아있는지
21. 기존 데이터를 불러온 뒤 "복제해서 새로 입력" → PK만 비고 나머지 값은
    유지된 채 새 입력 상태가 되는지

    않고** 몇 초 뒤 브라우저만 자동으로 열리는지 — 그 사이 브라우저에
    "불러오는 중" 화면이 잠깐 보였다가 자동으로 실제 대시보드로 바뀌는지

    입력 폼이 새 입력 상태로 열리는지

29. [변경] 탭 맨 위의 **변경 비교 기준 리셋** 버튼도 "간편 입력/저장" 창의
    버튼과 동일하게 동작하는지
30. 구매계약 탭(또는 다른 표 탭)을 보고 있는 상태에서 값을 저장 → 새로고침
    후 [홈]이 아니라 **보고 있던 그 탭으로 돌아오는지**. `#lookup=...`
    딥링크로 접속해 있는 상태에서 저장했을 때는 그 딥링크가 우선하는지
31. [홈] 탭의 **용량 정합성 분석**에서 계약이 없거나 부분/초과 계약된
    발전소·판매계약이 정확히 나열되는지, 클릭 시 해당 레코드 상세가 열리는지
32. [홈] 탭의 **우선순위 조치 필요 항목**이 문제 있는 항목 순으로 정렬되는지
    (0건인 항목은 초록, 문제 있는 항목은 빨강/주황으로 아래보다 위에), 각
    행 클릭 시 올바른 조건으로 필터링된 화면으로 이동하는지

걸리는 게 있으면 화면을 캡처해 보내주세요.

## 화면 구성

| 탭 | 내용 |
|---|---|
| **홈** | 설비용량·구매/판매 총량(**계약 종료 건 자동 제외 + 종료/만료 용량 별도 카드**)·수급 밸런스, 발전원별 비중, **용량 정합성 분석**(구매계약/판매계약 총 용량이 발전소/전기사용지 용량과 왜 다른지 발전소·계약 단위로 원인 분해), 수급매칭 **현황별 비율·용량**(상태 코드 순 정렬, 코드 없이 라벨만 표시), **년월별 추이**(조회 시작/종료 년월 직접 지정 가능), **우선순위 조치 필요 항목**(계약/공급 임박 알림 · 수급 불균형·미확보 모니터링 · 데이터 정합성 이상치 3개 카테고리, 위험/주의 뱃지)을 한 화면에. 항목을 누르면 해당 표/레코드로 **조건이 적용된 채** 이동. `요약 복사` 버튼으로 보고용 텍스트를 클립보드에 |
| **관계조회** | PK 하나를 고르면 FK로 이어진 다른 표의 행을 한 화면에 (발전소↔구매계약↔수급매칭↔전기사용지↔판매계약↔수요기업). `연결 범위`로 몇 단계까지 따라갈지 조절 |
| **탐색** | **기준 표와 출력 컬럼을 직접 골라** 여러 표를 합친 목록을 만듭니다. 연결 상대가 없는 행도 빈칸으로 남기므로 **누락 데이터**(구매계약 없는 발전소 등)를 그대로 찾아냅니다. 결과 검색은 여러 낱말을 공백으로 띄어 써도(예: "영광 풍력") 여러 컬럼에 걸쳐 찾고, 선택한 **출력 컬럼은 칩을 마우스로 끌어(드래그 앤 드롭) 표에 나오는 순서를 바꿀 수 있습니다**. 결과는 정렬·페이징되고 CSV/Excel/MD로 내려받을 수 있습니다 |
| **비교** | 레코드 최대 3건을 나란히 놓고 비교, 값이 다른 항목은 강조 |
| **표별 탭** | 검색·컬럼별 찾기·값 필터·기간 필터·정렬·페이징·컬럼 선택·행 클릭 상세·내려받기 |
| **변경** | 직전 생성분 대비 추가/수정/삭제(수정은 *이전값 → 새값*까지) + 여러 생성에 걸쳐 누적되는 "전체 변경 이력"(최대 1,000건, 검색/구분/표로 필터) |
| **검증** | PK공란·PK중복·FK공란·FK참조·조합중복. 클릭하면 문제의 레코드로 바로 이동 |

### 홈 탭 — 용량이 왜 차이 나는지, 지금 뭘 봐야 하는지

"구매계약 총 용량"이 "발전소 설비용량 합계"와 다른 이유를 숫자 차이만 보여
주지 않고, 발전소 단위로 원인을 쪼개서 설명합니다:

- **용량 정합성 분석** — 발전소 → 구매계약(공급 측), 판매계약 → 전기사용지
  (수요 측) 두 관계를 각각 분석해서, 차이를 "계약이 전혀 없는 발전소 N개
  (nMW)" + "부분 계약된 발전소의 미계약분 nMW" + "설비용량을 초과해 계약된
  발전소 N개(데이터 확인 필요)"로 분해해 보여줍니다. 차이가 큰 순서로 최대
  8건까지 나열하고, 클릭하면 그 발전소/계약의 상세 화면이 바로 열립니다.
- **우선순위 조치 필요 항목** — PPA 운영 실무 관점 3개 카테고리로 나눠
  보여줍니다: **계약/공급 임박 알림**(공급기한 D-30 이내 · D-31~60 — 이미
  만료된 건은 지금 손쓸 수 없는 사안이라 목록에서 제외), **수급 불균형·
  미확보 모니터링**(발전 설비용량 대비 미매칭 잔여용량 · 설비용량 초과
  계약 · 수요기업/공급자원 미확보), **데이터 정합성 이상치**(PK/FK 검증
  오류 · 날짜 역전 오류). 각 행은 위험(빨강)/주의(주황)/정상(회색) 뱃지를
  달고, 클릭하면 **해당 이슈에 해당하는 레코드만 필터링된 화면**으로 바로
  이동합니다(발전소/구매계약/판매계약 표에 "홈의 조치 필요 항목에서 이동"
  칩으로 표시되고, 눌러서 해제 가능).
- **구매/판매계약 총 용량 KPI** — 수급매칭 현황이 전부 "종료"류인 계약은
  자동으로 빼고 집계합니다("유효" 용량). 뺀 만큼은 옆의 **종료/만료 용량**
  카드에 건수·MW로 따로 표시되므로 숫자가 사라지지 않고 어디로 갔는지
  바로 보입니다.
- **수급매칭 현황별 비율·용량** — "1. 공급 중"처럼 앞에 번호가 붙은 값은
  코드 오름차순(1→99)으로 정렬하고, 화면에는 번호 없이 라벨만 보여줍니다.
- **년월별 추이 기간 필터** — 차트 위 조회 시작/종료 년월을 달력 선택
  또는 직접 입력(`YYYY-MM`)으로 바꾸면 차트·집계가 즉시 그 구간으로 다시
  그려집니다(한 번에 최대 36개월). 비워두면 기존처럼 최근 12개월을
  보여줍니다.

### 탐색 탭 — 엑셀에서 VLOOKUP 여러 번 걸던 작업을 화면에서

1. **기준 표** 선택 — 이 표의 각 행이 결과의 기준이 됩니다
2. **연결할 표** 선택 — FK 경로를 따라 자동 조인합니다. 중간에 거쳐야 하는 표는
   회색으로 자동 포함됩니다(예: 발전소 → 수급매칭을 고르면 구매계약이 자동 경유)
3. **출력 컬럼** 선택 — 어느 표의 어떤 컬럼이든 눌러서 켜고 끕니다
4. **결과** — 검색·정렬·페이징 + CSV/Excel/MD 내려받기 + 인쇄

연결 상대가 없는 행은 지우지 않고 `—`로 표시하며 행 전체를 주황색으로 강조합니다
(LEFT JOIN). `연결 여부` 선택으로 **누락된 행만**, **전부 연결된 행만**, 또는
**특정 표가 없는 행만** 골라볼 수 있고, 상단 `빠른 조회` 버튼은 스키마에서 자동으로
뽑은 질문(발전소 중 구매계약 없음, 전기사용지 중 수급매칭 없음 등)을 한 번에
설정해줍니다.

주요 편의 기능

- **통합 검색** — 상단 검색창 하나로 6개 표를 동시에 검색, 결과를 누르면 상세가 열림
- **조건부 색상** — 검증오류(빨강)·변경분(파랑)·신규(초록) 행, 미확보 배지,
  공급기한 만료/임박(D-n) 배지, 수급매칭 현황 색상
- **FK 이름 표시** — `P001` 옆에 `신안태양광1호 · 그린에너지(주)`처럼 이름을 같이
- **고정 헤더 + PK 열 고정** — 긴 표를 스크롤해도 기준이 안 흔들림
- **내려받기** — 지금 화면의 **필터·정렬·표시 컬럼이 그대로 반영된** 데이터를
  CSV / Excel(.xlsx) / Markdown 으로. 인쇄(Ctrl+P)하면 메뉴 없이 표만 깔끔하게
  나오고 브라우저의 "PDF로 저장"으로 PDF가 됩니다
- **반응형** — iPad 세로/휴대폰에서도 사용 가능
- **다크 모드**, **URL 공유**(`#lookup=표:PK` 링크로 특정 레코드 바로 열기),
  **최근 조회 5건**

## 변경 내역은 어떻게 잡히나요 (기준점 고정 방식)

서버도 DB도 없어서 실시간 변경이력을 남길 수 없기 때문에, **비교 기준이 되는
스냅샷(`<출력파일>_snapshot.json`)을 옆에 저장**해두고 그것과 비교합니다.
**이 기준점은 [변경] 탭(또는 실시간 입력 서버의 "간편 입력/저장" 창)의
"변경 비교 기준 리셋" 버튼을 누르기 전까지 절대 저절로 바뀌지 않습니다** —
그래서 리셋하기 전까지는 여러 번 실행/저장을 거듭해도 그 사이의 모든 변경이
계속 쌓여서 보입니다(예: 리셋 후 하루 종일 여러 번 저장해도, [변경] 탭에는
"오늘 아침 리셋 이후 지금까지" 바뀐 모든 것이 한 번에 보임). 별도 설정 없이
자동으로 동작하며, 첫 실행 다음부터 [변경] 탭이 채워집니다.

- 첫 실행: 비교 대상이 없으므로 [변경] 탭에 안내만 표시(이때의 데이터가
  자동으로 첫 기준점이 됨)
- 이후 실행: **기준점 대비** 누적 추가/수정/삭제가 표와 탭에 색으로 표시
- **삭제된 항목도 기준점에 저장된 값 그대로 전부 볼 수 있습니다** — [변경] 탭의
  "삭제된 항목" 목록에서 행을 클릭하면 그 레코드가 사라지기 직전, 기준점에 있던
  모든 컬럼 값을 상세 모달로 보여줍니다(추가/수정 항목은 지금 시트에 남아있으니
  표에서 바로 확인 가능 — 삭제된 것만 기준점이 유일한 출처라 별도 모달을 둠)
- **기준점을 새로 잡고 싶으면**: 실시간 입력 서버를 쓰고 있다면 **[변경] 탭
  맨 위**의 **[변경 비교 기준 리셋]** 버튼이나, "간편 입력/저장" 창 하단의
  같은 이름 버튼 — 둘 다 같은 동작입니다(어디서 누르든 편한 곳에서). 정적
  생성(`dashboard_recreate.bat`) 쪽은 `python build_dashboard.py ...
  --reset-snapshot`을 쓰세요. 리셋하면 그 순간이 새 기준점이 되어 그 이전
  변경 표시는 초기화됩니다.
- **리셋해도 아래 "전체 변경 이력"은 사라지지 않습니다** — 기준점 리셋은 [변경]
  탭의 "지금까지 쌓인 변경" 표시만 초기화할 뿐, 여러 번의 생성에 걸쳐 남는
  전체 이력 로그와는 별개입니다.
- 스냅샷 파일(`_snapshot.json`, `_lastbuild.json`)은 지우면 안 됩니다(지우면
  기준점/이력 계산이 깨집니다)
- 끄고 싶으면 `--no-snapshot`, 다른 스냅샷과 비교하려면 `--prev=경로`

### 전체 변경 이력 (여러 번의 생성에 걸쳐 누적)

위 스냅샷 비교는 **"직전 생성분과 이번 생성분"** 딱 두 시점만 비교합니다.
그와 별개로, [변경] 탭에는 **여러 번의 생성에 걸쳐 계속 쌓이는** "전체 변경
이력" 목록도 있습니다 — 지난주에 추가한 항목, 어제 수정한 항목까지 한
목록에서 검색어/구분(추가·수정·삭제)/표로 걸러가며 찾을 수 있습니다.

- 대시보드를 만들 때마다(`build_dashboard.py`/`dashboard_recreate.bat`/실시간
  입력 서버의 자동 새로고침 전부 포함) 이번에 새로 잡힌 추가/수정/삭제 건이
  `<출력파일>_changelog.json`에 그대로 이어붙습니다(첫 실행처럼 비교 대상이
  없을 때는 아무것도 안 쌓입니다).
- 최대 **1,000건**까지 보존하고, 넘으면 **가장 오래된 것부터** 자동으로
  빠집니다(최근 1,000건은 항상 남아있음).
- `_snapshot.json`과 마찬가지로 이 파일도 지우면 안 됩니다(지우면 그동안
  쌓인 이력이 사라집니다) — 함께 옮기고 함께 백업하세요.
- 각 이력 항목에는 **누가 바꿨는지**(`actor`)도 함께 기록됩니다. 실시간 입력
  서버로 저장/삭제한 경우 브라우저에 저장해둔 "표시 이름"(간편 입력 폼 상단
  👤 칸, 비워두면 그 PC의 Windows 로그인 계정)이, `dashboard_recreate.bat`/
  `build_dashboard.py`로 만든 경우 그 스크립트를 실행한 PC의 Windows 로그인
  계정이 자동으로 쓰입니다. 로그인 계정을 못 읽으면 "알 수 없음"으로 남습니다.

| `make_demo.py` | 화면 확인용 데모(의도적 오류·변경 케이스 포함) 생성기 |
| `vendor/` | **동봉된 openpyxl** — pip install도, 인터넷 연결도 필요 없습니다 |
| `excel_com.py` | Windows COM(pywin32)으로 열려 있는 엑셀을 직접 읽고 쓰는 모듈 |
| `ppa_liveserver.py` | 입력/저장을 엑셀에 실시간 반영하는 웹 서버 (`excel_com.py` 사용) |
| `dashboard_form.js` | 대시보드에 주입되는 "간편 입력/저장" 플로팅 폼 — 개별입력, 컬럼별 검색, 그룹A/B 일괄 입력·삭제 포함 (서버 실행 시에만 동작) |
| `run_live_server_hidden.vbs` | `ppa_liveserver.py`를 콘솔 창 없이 백그라운드로 띄우는 실행 파일 (권장, 실패 시에만 안내 창) |
| `_run_server_hidden_worker.bat` | 위 vbs가 내부적으로만 쓰는 실행 도우미 (직접 실행하지 않음) |
| `run_live_server.bat` | `ppa_liveserver.py`를 콘솔 창을 보여주며 실행하는 더블클릭용 배치파일 (디버깅용) |
| `stop_live_server.bat` | 떠 있는 서버를 확실히 종료 (읽기 전용 문제 해결용) |
| `live_server.log` | (실행 시 생성) 숨김 실행 방식의 서버 출력 로그 — 콘솔이 없어 화면에 안 보이는 대신 여기 남음 |

## pip도, 인터넷도 필요 없습니다 (openpyxl 동봉됨)

`vendor/` 폴더에 openpyxl을 미리 넣어뒀습니다(순수 Python이라 폴더째 복사만
하면 어디서든 동작). `ppa_loader.py`가 자동으로 `vendor/`를 먼저 찾아 쓰므로
**`pip install`을 못 하는 환경에서도 xlsm 방식이 그대로 됩니다.** 이 폴더를
통째로(=`vendor/` 포함) 옮기세요 — 일부 파일만 옮기면 안 됩니다.

## Python 자체가 안 깔려있다면

1. 인터넷 되는 PC에서 <https://www.python.org/downloads/windows/> 접속
2. "Windows embeddable package (64-bit)" zip 다운로드 (설치 없이 압축만 풀면 되는 휴대용 버전)
3. 압축 푼 내용물을 `static-dashboard` 폴더 **옆에** `python-embed/` 폴더로 배치
4. VDI에서는 그 폴더의 `python.exe`를 직접 실행:
   ```powershell
   ..\python-embed\python.exe build_dashboard.py --xlsm="...\PPA파일.xlsm"
   ```

> 참고: embeddable 버전은 `pythonXXX._pth` 때문에 실행 스크립트 폴더가
> 자동으로 `sys.path`에 들어가지 않습니다. 그래서 `build_dashboard.py`와
> `make_demo.py` 첫머리에서 자기 폴더를 직접 `sys.path`에 추가합니다.

## 실제 데이터로 생성하기

**Windows에서 매번 다시 만들기 — `dashboard_recreate.bat` (추천)**

이 폴더의 `dashboard_recreate.bat`을 더블클릭하면 됩니다. 이 폴더 바로 위(상위
폴더)에 있는 xlsm 파일을 자동으로 찾고, 출력 파일명(`PPA현황.html`)과 스냅샷
경로를 매번 고정해서 [변경] 탭 비교가 실행할 때마다 끊기지 않고 이어지게
합니다. 아래 폴더 구조를 그대로 맞춰주세요.

```
📁 (작업 폴더)\
   PPA파일.xlsm              ← 실제 엑셀 파일 (하나만)
   📁 static-dashboard\       ← 이 폴더 전체(=지금 README가 있는 폴더)
      dashboard_recreate.bat
      build_dashboard.py, ppa_*.py, vendor\...
```

엑셀 안에서 버튼 하나로 실행하고 싶으면 `../vba-form/README_대시보드생성.md`도
같이 보세요(`PPA_대시보드생성.bas` — 저장 → 버튼 클릭 → 이 배치파일을 자동으로
실행하고 결과를 엽니다).

**방법 A — xlsm 파일 직접 사용 (동봉된 openpyxl 사용, pip 불필요)**
```bash
python3 build_dashboard.py --xlsm=/path/to/PPA파일.xlsm
```

**방법 B — CSV 폴더 사용 (vendor/도 필요 없는 가장 가벼운 방식)**

엑셀에서 각 시트를 `다른 이름으로 저장 → CSV UTF-8`로 내보내 시트 이름과 똑같은
파일명(`T_발전소.csv` 등)으로 한 폴더에 모은 뒤:
```bash
python3 build_dashboard.py --csv-dir=/path/to/csv폴더
```

옵션

| 옵션 | 설명 |
|---|---|
| `--out=파일명.html` | 출력 파일명 (기본 `PPA현황.html`) |
| `--prev=경로` | 비교할 이전 스냅샷 지정 (기본: `<출력파일>_snapshot.json`) |
| `--no-snapshot` | 이번 실행 결과를 스냅샷으로 저장하지 않음 |

- 표 이름과 헤더 텍스트로 자동 매칭하며, PK중복/PK공란/*참조/조합중복 같은
  검증 열은 자동으로 건너뜁니다(실행 로그의 "인식 안 된 헤더"는 정상입니다).
- OneDrive 동기화 폴더의 파일을 바로 읽으면 `BadZipFile` 오류가 날 수 있습니다.
  로컬 폴더로 복사한 사본을 지정하는 것을 권장합니다.

## 검증됨

실제 운영 규모와 같은 합성 데이터(발전소 589 · 구매계약 615 · 수요기업 49 ·

- 초기 렌더 0.3초, 615행 표에서 실제 타이핑 검색·정렬 각 0.3초 이내,
  1,900여 행 전체 통합검색 0.1초
- 생성한 `.xlsx`를 openpyxl로 다시 열어 시트 구성·숫자 타입·헤더 서식까지 확인
  (경고 없이 열림), CSV는 UTF-8 BOM + CRLF + 전체 인용 처리 확인
- 페이징 경계, 컬럼 숨김이 표·관계조회·비교·내려받기에 일관 적용되는지,
  검증/변경 색상과 집계가 일치하는지, URL 해시 왕복, ESC 모달 닫기 확인
- 다대다 구조(한 전기사용지가 여러 구매계약에서 공급) 때문에 관계조회를
  제한 없이 펼치면 수백 건이 딸려오는 문제를 발견해 **연결 범위 선택(기본
  2단계) + 표별 50건 표시 상한**으로 해결
- 탐색 탭의 조인 결과는 원본 데이터로 따로 계산한 기대값과 대조해 확인했습니다
  (발전소⋈구매계약 823행, 구매계약 없는 발전소 208건, 전기사용지⋈수급매칭 468행,
  수급매칭 없는 전기사용지 1건, 판매계약 없는 수요기업 7건, 3단 조인 956행 — 전부 일치)
