# PPA 계약관리 — 정적 HTML 대시보드 (임시 · 서버 불필요)

`backend`/`frontend`의 편집 가능한 웹앱을 올릴 사내망 서버가 아직 없는 동안,
**서버 없이 지금 바로 쓸 수 있는 조회 전용 대시보드**입니다. 사내에서 이미
검증된 패턴(정산 대시보드: `ppa_core.py`/`ppa_pipeline.py`/`dashboard_render.py`)을
그대로 따랐습니다 — 데이터를 JSON으로 HTML 안에 통째로 넣고 JS로 처리하는
단일 파일. **외부 CDN·폰트·라이브러리를 하나도 쓰지 않아** 인터넷이 안 되는
VDI에서도 그대로 열리고, 만들어진 HTML 파일 하나만 공유폴더·메일·Teams로
보내면 누구나 브라우저로 바로 봅니다.

## ⚠️ `dashboard_recreate.bat`으로 만든 HTML 파일은 조회 전용입니다

`build_dashboard.py`/`dashboard_recreate.bat`으로 만든 `PPA현황.html`은 그
자체로는 값을 고쳐서 저장하는 기능이 없습니다 — 서버가 없는 순수 HTML
파일이라 팀원들에게 메일/Teams로 보내서 보는 용도입니다. 이 경우 **데이터
수정은 계속 엑셀에서** 하고, 최신 상태를 보여주고 싶을 때 배치파일을 다시
실행해 HTML을 새로 만들면 됩니다.

**입력까지 브라우저에서 하고 싶다면** 아래 "실시간 입력 서버" 절을 보세요 —
서버 하나를 띄우는 대신, 저장을 누르면 실제로 엑셀에 반영됩니다.

## 실시간 입력 서버 — 브라우저에서 입력하면 엑셀에 바로 반영 (선택 기능)

`ppa_liveserver.py`를 실행하면(더블클릭용 `run_live_server.bat` 제공) 계속
떠 있는 작은 웹 서버가 뜨고, 대시보드 화면 오른쪽 아래에 **"간편 입력/저장"**
버튼이 나타납니다. 표를 고르고 값을 입력해 저장을 누르면:

1. `excel_com.py`가 **Windows COM으로 엑셀 프로그램 자체를 직접 조작**해서
   그 값을 씁니다 — 파일을 열어 덮어쓰는 게 아니라, 진짜 엑셀이 하는 것과
   똑같은 방식입니다. 그래서 openpyxl이 못 여는 예전 바이너리(CFB) 포맷
   xlsm에도 그대로 동작합니다.
2. **그 순간 엑셀 파일이 열려 있으면 그 세션에 바로 씁니다** — 화면의 셀이
   바로 바뀝니다. 저장을 먼저 요구하지 않고, 지금 화면(메모리) 상태를
   그대로 읽어갑니다. 열려 있지 않으면 보이지 않는 새 엑셀 인스턴스를 띄워
   열고 저장한 뒤 그 인스턴스만 조용히 닫습니다(사용자가 나중에 여는 세션과는
   무관).
3. 저장 전에 PK 공란·FK 참조(존재하지 않는 발전소ID 등)를 확인해서, 문제가
   있으면 엑셀에 쓰지 않고 오류를 먼저 보여줍니다.
4. 저장이 끝나면 서버가 바로 다시 읽어 `PPA현황.html`을 갱신하고 화면도
   새로고침됩니다 — 별도로 "대시보드 생성"을 다시 누를 필요가 없습니다.

### 실행 방법

```
📁 (작업 폴더)\
   PPA파일.xlsm
   📁 static-dashboard\
      run_live_server.bat     ← 더블클릭 (또는 엑셀의 [실시간 입력 서버 시작] 버튼)
      ppa_liveserver.py, excel_com.py, dashboard_form.js
      dashboard_recreate.bat, build_dashboard.py, ppa_*.py, vendor\...
```

`run_live_server.bat`을 더블클릭하면 상위 폴더의 xlsm을 자동으로 찾아
`http://127.0.0.1:8842`에서 서버를 띄우고 브라우저를 자동으로 엽니다. 이
창(검은 콘솔)을 닫으면 서버도 함께 종료됩니다. 엑셀 안에서 실행하고 싶으면
`../vba-form/README_대시보드생성.md`의 **[실시간 입력 서버 시작]** 버튼을
쓰세요.

### pywin32 설치 (필수)

이 기능은 openpyxl이 아니라 **Windows COM 자동화**를 쓰므로 `pywin32`가
반드시 있어야 합니다. openpyxl과 달리 컴파일된 패키지라 `vendor/`처럼
파일만 복사해 넣을 수 없습니다.

- **인터넷이 되는 VDI라면**: `python -m pip install pywin32`
  (또는 `..\python-embed\python.exe -m pip install pywin32` — embeddable
  배포본은 기본적으로 pip이 없으므로, 먼저 <https://bootstrap.pypa.io/get-pip.py>를
  같은 방식으로 받아 `python.exe get-pip.py`로 pip을 넣어야 합니다)
- **인터넷이 안 되는 VDI라면**: 인터넷 되는 PC에서
  `pip download pywin32 --no-deps -d ./pywin32_offline`으로 해당 VDI의 Python
  버전/아키텍처에 맞는 `.whl` 파일을 받아 옮긴 뒤,
  `python -m pip install --no-index --find-links=./pywin32_offline pywin32`
- 이 모듈은 `win32com.client.Dispatch`/`GetObject`(동적 바인딩)만 사용하므로
  pywin32 설치 후 흔히 필요한 `pywin32_postinstall.py -install`(레지스트리
  등록) 단계는 **필요 없습니다** — 패키지만 있으면 바로 동작합니다.
- pywin32가 없으면 `run_live_server.bat`이 서버를 띄우기 전에 바로 감지해서
  안내하고 멈춥니다(조용히 실패하지 않습니다).

### 동시 접근/충돌에 대해 알아둘 것

- 저장은 **서버 안의 전용 스레드 하나가 순서대로 처리**합니다 — 두 사람이
  동시에 저장 버튼을 눌러도 한 번에 하나씩만 엑셀에 반영되고, 같은 행을
  두고 덮어쓰는 경합은 나지 않습니다.
- 하지만 **사용자가 엑셀에서 같은 셀을 직접 타이핑하고 있는 도중**에
  브라우저 쪽 저장이 들어오면, 화면의 셀 값이 사용자 모르게 바뀔 수
  있습니다 — 지금 열려 있는 세션에 바로 쓰는 방식을 택했기 때문에 생기는
  당연한 트레이드오프입니다(파일을 닫아야만 저장되게 하는 더 안전하지만
  불편한 대안도 있습니다 — 필요하면 말씀해주세요).
- 표(ListObject)가 있는 시트는 새 행을 추가할 때 표를 확장해서(서식·필터
  유지) 넣고, 없으면 마지막 사용 행 바로 다음에 씁니다.
- `dashboard_recreate.bat`(서버 없음, openpyxl 기반)과 이 서버(COM 기반)는
  같은 `PPA현황.html`/`PPA현황_snapshot.json`을 공유합니다 — 어느 쪽으로
  갱신하든 [변경] 탭 누적 비교는 그대로 이어집니다.

### "같은 이름의 통합 문서가 이미 열려 있습니다" 류의 엑셀 오류가 뜬다면

이미 그 파일이 열려 있는데도 서버가 그걸 못 찾고 **새로 하나 더 열려다가**
나는 오류입니다(엑셀은 같은 이름의 파일을 두 번 동시에 열 수 없어서 이때
"파일 이름이나 경로가 없습니다 / 다른 프로그램에서 사용 중입니다 / 이미
열려 있는 통합 문서와 이름이 같습니다"라는 안내를 냅니다). 엑셀 프로세스가
여러 개 떠 있거나(워크북마다 별도 창), OneDrive 경로 표기 차이 때문에
"이미 열려 있음"을 놓치면 생길 수 있던 문제라 파일 경로로 직접 찾는 방식
(`GetObject(파일경로)`)으로 바꿔뒀습니다 — 그래도 이 오류가 다시 나면
캡처해서 보내주세요(어느 단계인지 원본 오류까지 같이 보이도록 고쳐뒀습니다).

### 확인된 범위 / 먼저 봐주실 것

이 환경에는 Windows/Excel이 없어 COM 호출을 실제로 실행해보지 못했습니다
(문법·모듈 구조·pywin32 없을 때의 오류 메시지까지만 검증). 사본에서 아래
순서로 확인해주세요.

1. pywin32 설치 후 `run_live_server.bat` 실행 → 콘솔에 `[OK] 서버 시작` 이
   뜨고 브라우저가 자동으로 열리는지
2. 엑셀에서 그 xlsm을 열어둔 채로 브라우저에서 값을 입력해 저장 → 엑셀
   화면의 셀이 저장을 누르는 즉시 바뀌는지, `wb.Save()`가 실제로 파일에도
   반영되는지(제목표시줄에 "저장되지 않음" 표시가 안 남는지)
3. 엑셀을 완전히 닫은 상태에서 저장 → 새 셀 값이 들어가고, 작업 관리자에
   여분의 EXCEL.EXE 프로세스가 남지 않는지(우리가 띄운 인스턴스가 제대로
   종료되는지)
4. 존재하지 않는 발전소ID로 구매계약을 저장 시도 → 엑셀에 쓰지 않고 오류
   메시지가 먼저 뜨는지
5. 새 PK로 저장(추가) → 표(ListObject) 서식이 새 행까지 그대로 이어지는지
6. 저장 직후 대시보드 화면이 자동으로 새로고침되고 [변경] 탭에 방금 저장한
   항목이 뜨는지
7. 엑셀 쪽 버튼(`../vba-form/README_대시보드생성.md`의 [실시간 입력 서버
   시작])으로도 같은 서버가 뜨는지

걸리는 게 있으면 화면을 캡처해 보내주세요.

## 화면 구성

| 탭 | 내용 |
|---|---|
| **홈** | 설비용량·구매/판매 총량·수급 밸런스, 발전원별 비중, 미확보·공급기한 임박·검증오류를 한 화면에. 항목을 누르면 해당 표로 **조건이 적용된 채** 이동. `요약 복사` 버튼으로 보고용 텍스트를 클립보드에 |
| **관계조회** | PK 하나를 고르면 FK로 이어진 다른 표의 행을 한 화면에 (발전소↔구매계약↔수급매칭↔전기사용지↔판매계약↔수요기업). `연결 범위`로 몇 단계까지 따라갈지 조절 |
| **탐색** | **기준 표와 출력 컬럼을 직접 골라** 여러 표를 합친 목록을 만듭니다. 연결 상대가 없는 행도 빈칸으로 남기므로 **누락 데이터**(구매계약 없는 발전소 등)를 그대로 찾아냅니다. 결과는 검색·정렬·페이징되고 CSV/Excel/MD로 내려받을 수 있습니다 |
| **비교** | 레코드 최대 3건을 나란히 놓고 비교, 값이 다른 항목은 강조 |
| **표별 탭** | 검색·컬럼별 찾기·값 필터·기간 필터·정렬·페이징·컬럼 선택·행 클릭 상세·내려받기 |
| **변경** | 직전 생성분 대비 추가/수정/삭제. 수정은 *이전값 → 새값*까지 |
| **검증** | PK공란·PK중복·FK공란·FK참조·조합중복. 클릭하면 문제의 레코드로 바로 이동 |

### 탐색 탭 — 엑셀에서 VLOOKUP 여러 번 걸던 작업을 화면에서

1. **기준 표** 선택 — 이 표의 각 행이 결과의 기준이 됩니다
2. **연결할 표** 선택 — FK 경로를 따라 자동 조인합니다. 중간에 거쳐야 하는 표는
   회색으로 자동 포함됩니다(예: 발전소 → 수급매칭을 고르면 구매계약이 자동 경유)
3. **출력 컬럼** 선택 — 어느 표의 어떤 컬럼이든 눌러서 켜고 끕니다
4. **결과** — 검색·정렬·페이징 + CSV/Excel/MD 내려받기 + 인쇄

연결 상대가 없는 행은 지우지 않고 `—`로 표시하며 행 전체를 주황색으로 강조합니다
(LEFT JOIN). `연결 여부` 선택으로 **누락된 행만**, **전부 연결된 행만**, 또는
**특정 표가 없는 행만** 골라볼 수 있고, 상단 `빠른 조회` 버튼은 스키마에서 자동으로
뽑은 질문(발전소 중 구매계약 없음, 전기사용지 중 수급매칭 없음 등)을 한 번에
설정해줍니다.

주요 편의 기능

- **통합 검색** — 상단 검색창 하나로 6개 표를 동시에 검색, 결과를 누르면 상세가 열림
- **조건부 색상** — 검증오류(빨강)·변경분(파랑)·신규(초록) 행, 미확보 배지,
  공급기한 만료/임박(D-n) 배지, 수급매칭 현황 색상
- **FK 이름 표시** — `P001` 옆에 `신안태양광1호 · 그린에너지(주)`처럼 이름을 같이
- **고정 헤더 + PK 열 고정** — 긴 표를 스크롤해도 기준이 안 흔들림
- **내려받기** — 지금 화면의 **필터·정렬·표시 컬럼이 그대로 반영된** 데이터를
  CSV / Excel(.xlsx) / Markdown 으로. 인쇄(Ctrl+P)하면 메뉴 없이 표만 깔끔하게
  나오고 브라우저의 "PDF로 저장"으로 PDF가 됩니다
- **반응형** — iPad 세로/휴대폰에서도 사용 가능
- **다크 모드**, **URL 공유**(`#lookup=표:PK` 링크로 특정 레코드 바로 열기),
  **최근 조회 5건**

## 변경 내역은 어떻게 잡히나요 (스냅샷 방식)

서버도 DB도 없어서 실시간 변경이력을 남길 수 없기 때문에, **대시보드를 만들 때마다
그 시점의 데이터를 스냅샷(`<출력파일>_snapshot.json`)으로 옆에 저장**해두고
다음 실행 때 그것과 비교합니다. 별도 설정 없이 자동으로 동작하며, 두 번째
실행부터 [변경] 탭이 채워집니다.

- 첫 실행: 비교 대상이 없으므로 [변경] 탭에 안내만 표시
- 이후 실행: 지난번 대비 추가/수정/삭제가 표와 탭에 색으로 표시
- **삭제된 항목도 스냅샷에 저장된 값 그대로 전부 볼 수 있습니다** — [변경] 탭의
  "삭제된 항목" 목록에서 행을 클릭하면 그 레코드가 사라지기 직전, 스냅샷에 있던
  모든 컬럼 값을 상세 모달로 보여줍니다(추가/수정 항목은 지금 시트에 남아있으니
  표에서 바로 확인 가능 — 삭제된 것만 스냅샷이 유일한 출처라 별도 모달을 둠)
- 스냅샷 파일은 지우면 안 됩니다(지우면 다음 실행이 다시 "첫 실행"이 됩니다)
- 끄고 싶으면 `--no-snapshot`, 다른 스냅샷과 비교하려면 `--prev=경로`

## 파일 구성

| 파일 | 역할 |
|---|---|

## pip도, 인터넷도 필요 없습니다 (openpyxl 동봉됨)

`vendor/` 폴더에 openpyxl을 미리 넣어뒀습니다(순수 Python이라 폴더째 복사만
하면 어디서든 동작). `ppa_loader.py`가 자동으로 `vendor/`를 먼저 찾아 쓰므로
**`pip install`을 못 하는 환경에서도 xlsm 방식이 그대로 됩니다.** 이 폴더를
통째로(=`vendor/` 포함) 옮기세요 — 일부 파일만 옮기면 안 됩니다.

## Python 자체가 안 깔려있다면

1. 인터넷 되는 PC에서 <https://www.python.org/downloads/windows/> 접속
2. "Windows embeddable package (64-bit)" zip 다운로드 (설치 없이 압축만 풀면 되는 휴대용 버전)
3. 압축 푼 내용물을 `static-dashboard` 폴더 **옆에** `python-embed/` 폴더로 배치
4. VDI에서는 그 폴더의 `python.exe`를 직접 실행:
   ```powershell
   ..\python-embed\python.exe build_dashboard.py --xlsm="...\PPA파일.xlsm"
   ```

> 참고: embeddable 버전은 `pythonXXX._pth` 때문에 실행 스크립트 폴더가
> 자동으로 `sys.path`에 들어가지 않습니다. 그래서 `build_dashboard.py`와
> `make_demo.py` 첫머리에서 자기 폴더를 직접 `sys.path`에 추가합니다.

## 실제 데이터로 생성하기

**Windows에서 매번 다시 만들기 — `dashboard_recreate.bat` (추천)**

이 폴더의 `dashboard_recreate.bat`을 더블클릭하면 됩니다. 이 폴더 바로 위(상위
폴더)에 있는 xlsm 파일을 자동으로 찾고, 출력 파일명(`PPA현황.html`)과 스냅샷
경로를 매번 고정해서 [변경] 탭 비교가 실행할 때마다 끊기지 않고 이어지게
합니다. 아래 폴더 구조를 그대로 맞춰주세요.

```
📁 (작업 폴더)\
   PPA파일.xlsm              ← 실제 엑셀 파일 (하나만)
   📁 static-dashboard\       ← 이 폴더 전체(=지금 README가 있는 폴더)
      dashboard_recreate.bat
      build_dashboard.py, ppa_*.py, vendor\...
```

엑셀 안에서 버튼 하나로 실행하고 싶으면 `../vba-form/README_대시보드생성.md`도
같이 보세요(`PPA_대시보드생성.bas` — 저장 → 버튼 클릭 → 이 배치파일을 자동으로
실행하고 결과를 엽니다).

**방법 A — xlsm 파일 직접 사용 (동봉된 openpyxl 사용, pip 불필요)**
```bash
python3 build_dashboard.py --xlsm=/path/to/PPA파일.xlsm
```

**방법 B — CSV 폴더 사용 (vendor/도 필요 없는 가장 가벼운 방식)**

엑셀에서 각 시트를 `다른 이름으로 저장 → CSV UTF-8`로 내보내 시트 이름과 똑같은
파일명(`T_발전소.csv` 등)으로 한 폴더에 모은 뒤:
```bash
python3 build_dashboard.py --csv-dir=/path/to/csv폴더
```

옵션

| 옵션 | 설명 |
|---|---|
| `--out=파일명.html` | 출력 파일명 (기본 `PPA현황.html`) |
| `--prev=경로` | 비교할 이전 스냅샷 지정 (기본: `<출력파일>_snapshot.json`) |
| `--no-snapshot` | 이번 실행 결과를 스냅샷으로 저장하지 않음 |

- 표 이름과 헤더 텍스트로 자동 매칭하며, PK중복/PK공란/*참조/조합중복 같은
  검증 열은 자동으로 건너뜁니다(실행 로그의 "인식 안 된 헤더"는 정상입니다).
- OneDrive 동기화 폴더의 파일을 바로 읽으면 `BadZipFile` 오류가 날 수 있습니다.
  로컬 폴더로 복사한 사본을 지정하는 것을 권장합니다.

## 검증됨

실제 운영 규모와 같은 합성 데이터(발전소 589 · 구매계약 615 · 수요기업 49 ·
판매계약 95 · 전기사용지 107 · 수급매칭 467행)로 헤드리스 브라우저에서
직접 조작하며 확인했습니다.

- 초기 렌더 0.3초, 615행 표에서 실제 타이핑 검색·정렬 각 0.3초 이내,
  1,900여 행 전체 통합검색 0.1초
- 생성한 `.xlsx`를 openpyxl로 다시 열어 시트 구성·숫자 타입·헤더 서식까지 확인
  (경고 없이 열림), CSV는 UTF-8 BOM + CRLF + 전체 인용 처리 확인
- 페이징 경계, 컬럼 숨김이 표·관계조회·비교·내려받기에 일관 적용되는지,
  검증/변경 색상과 집계가 일치하는지, URL 해시 왕복, ESC 모달 닫기 확인
- 다대다 구조(한 전기사용지가 여러 구매계약에서 공급) 때문에 관계조회를
  제한 없이 펼치면 수백 건이 딸려오는 문제를 발견해 **연결 범위 선택(기본
  2단계) + 표별 50건 표시 상한**으로 해결
- 탐색 탭의 조인 결과는 원본 데이터로 따로 계산한 기대값과 대조해 확인했습니다
  (발전소⋈구매계약 823행, 구매계약 없는 발전소 208건, 전기사용지⋈수급매칭 468행,
  수급매칭 없는 전기사용지 1건, 판매계약 없는 수요기업 7건, 3단 조인 956행 — 전부 일치)
