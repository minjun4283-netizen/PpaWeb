# PPA 대시보드 생성 버튼 (엑셀 VBA)

엑셀에서 벗어나지 않고 **버튼 하나로** 조회용 HTML 대시보드(`PPA현황.html`)를
다시 만듭니다. 지금까지는 `static-dashboard\dashboard_recreate.bat`을 탐색기에서
직접 찾아 더블클릭해야 했는데, 이 모듈을 넣으면 엑셀 안에서 끝납니다.

이 폼은 **값을 저장하지 않습니다.** 입력/수정은 여전히 `PPA_통합입력폼`
(`입력폼` 시트) 또는 `PPA_탐색폼`(`탐색` 시트)에서 하고, 이 버튼은 "지금
엑셀에 저장된 내용을 HTML로 다시 뽑아내는" 역할만 합니다.

```
① 데이터 입력/수정  →  입력폼 또는 탐색 시트 (저장까지)
② 대시보드 생성      →  대시보드생성 시트의 [대시보드 생성] 버튼
③ 자동으로 PPA현황.html 이 열리고, [변경] 탭에 ①에서 바뀐 내용이 표시됨
```

## 왜 필요한가 — "누적되지 않고 초기화된다"는 문제

`build_dashboard.py`는 실행할 때마다 그 시점 데이터를 `PPA현황_snapshot.json`에
저장해두고, 다음 실행 때 그 파일과 비교해서 [변경] 탭을 채웁니다. 이 비교가
계속 이어지려면 **매번 같은 폴더에서, 같은 출력 파일명으로** 실행돼야 합니다 —
더블클릭 위치가 매번 달라지거나 출력 파일명이 바뀌면 스냅샷을 못 찾아 매번
"첫 실행"처럼 리셋된 것처럼 보입니다.

이번에 새로 만든 `dashboard_recreate.bat`은 **자기 자신이 있는 폴더 기준으로만**
동작하고 출력 파일명(`PPA현황.html`)도 고정해뒀습니다. 이 버튼으로 실행하면
그 `.bat`을 그대로 호출하므로 항상 같은 스냅샷과 비교됩니다. 실행할 때마다
화면에 "비교 대상 스냅샷: … 있음/없음"이 표시되니, 매번 같은 파일을 보고 있는지
직접 확인할 수 있습니다.

## 폴더 구조 (중요)

이 버튼은 통합문서 바로 옆에 `static-dashboard` 폴더가 있다고 가정합니다.

```
📁 (작업 폴더)\
   PPA파일.xlsm              ← 이 통합문서 (입력폼·탐색·대시보드생성 매크로 포함)
   📁 static-dashboard\
      dashboard_recreate.bat  ← 버튼이 실행하는 배치파일
      build_dashboard.py, ppa_*.py, vendor\...
      PPA현황.html            ← 생성 결과 (자동으로 열림)
      PPA현황_snapshot.json   ← 자동 갱신 - 지우지 마세요
   📁 python-embed\           ← python 미설치 환경만 필요
```

xlsm이 OneDrive 동기화 폴더 안에 있으면 `.bat`이 실행 중 참고 메시지를 띄웁니다
(동기화가 덜 됐거나 다른 프로그램이 파일을 열어둔 상태면 오류가 날 수 있음 —
`static-dashboard/README.md`의 기존 안내대로 로컬 사본 사용을 권장).

## 설치

1. 원본 xlsm의 **사본**에서 먼저 시험하세요.
2. GitHub에서 **Code → Download ZIP**으로 받습니다(Raw 우클릭 저장은 UTF-8이라
   한글이 깨집니다 — 다른 두 모듈과 동일한 주의사항).
3. `static-dashboard` 폴더 전체를 xlsm과 같은 폴더에 둡니다(위 구조대로).
4. 엑셀에서 `Alt`+`F11` → **파일 → 파일 가져오기** → `PPA_대시보드생성.bas` 선택
5. 왼쪽 목록에 `PPA_DashboardGen` 모듈이 한글 깨짐 없이 들어왔는지 확인
   (깨졌다면 `README.md`의 "이미 오류가 났다면" 절차 참고 — 세 모듈 모두 동일)
6. VBE를 닫고 `Alt`+`F8` → **대시보드_만들기** → 실행
7. `대시보드생성` 시트가 생기고 버튼이 놓입니다. 이후로는 버튼만 쓰면 됩니다.

`입력폼`(PPA_InputForm), `탐색`(PPA_Explorer)과 **완전히 독립적으로 동작**합니다.
셋 다 가져와도 되고, 필요한 것만 가져와도 됩니다.

## 버튼을 누르면 일어나는 일

1. 저장 안 한 변경사항이 있으면 저장할지 먼저 물어봅니다(대시보드는 디스크에
   저장된 내용만 읽으므로, 저장 안 하면 방금 입력한 내용이 안 잡힙니다).
2. `static-dashboard\dashboard_recreate.bat`을 **이 통합문서의 정확한 경로**를
   인자로 넘겨 실행합니다 — 어떤 xlsm을 읽을지 추측할 필요가 없습니다.
3. 배치파일이 끝날 때까지 엑셀이 기다립니다(진행 상황이 검은 창에 그대로
   보입니다). 시트의 "상태" 칸도 같이 갱신됩니다.
4. 성공하면 `PPA현황.html`이 자동으로 열립니다.

## 회사 보안 정책으로 매크로의 외부 프로그램 실행이 막혀 있다면

일부 VDI는 매크로가 `Shell`/`WScript.Shell`로 다른 프로그램을 실행하는 것을
막아둡니다. 이 경우 버튼을 눌러도 "배치파일을 실행하지 못했습니다" 오류가
납니다 — 그러면 `static-dashboard` 폴더에서 `dashboard_recreate.bat`을
**직접 더블클릭**해서 실행하면 됩니다(버튼과 결과는 동일, 자동 연결만 없을 뿐).

## ⚠️ 파일 인코딩 주의

다른 두 모듈과 동일합니다 — `.bas`는 ANSI(CP949)로 저장돼 있어야 VBE 가져오기에서
한글이 안 깨집니다. 자세한 원인과 "허가된 개체 이름이 아닙니다" 오류 대처법은
`README.md`를 참고하세요.

## 확인된 범위 / 먼저 봐주실 것

정적 점검(프로시저 정의·호출 인자 수·블록 짝·중복 선언·`Option Explicit` 위반)은
통과했지만, **이 환경에는 엑셀이 없어 실제로 실행해보지 못했습니다.** 사본에서
아래 순서로 확인해주세요.

1. `대시보드_만들기` 실행 → `대시보드생성` 시트와 버튼이 생기는지
2. 버튼 클릭 → 검은 창(배치파일)이 뜨고 "대상 엑셀 파일"에 지금 이 통합문서의
   경로가 정확히 나오는지
3. 완료 후 `PPA현황.html`이 자동으로 열리고, 시트의 "상태" 칸에 성공 시각이
   찍히는지
4. 아무 셀 하나를 고치고 저장 → 버튼을 다시 누르기 → 새로 열린 HTML의 [변경]
   탭에 그 항목이 "수정"으로 뜨는지 (누적 문제가 실제로 고쳐졌는지 확인하는
   핵심 단계)
5. `static-dashboard` 폴더가 없거나 이름이 다를 때 → 버튼을 누르면 정확한
   위치를 알려주며 멈추는지(조용히 실패하지 않는지)

걸리는 게 있으면 화면을 캡처해 보내주세요.
