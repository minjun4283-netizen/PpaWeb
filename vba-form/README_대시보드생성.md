# PPA 대시보드 생성 / 실시간 입력 서버 버튼 (엑셀 VBA)

엑셀에서 벗어나지 않고 **버튼으로** `static-dashboard` 폴더의 배치파일을
실행합니다. 이 모듈이 만드는 `대시보드생성` 시트에는 버튼이 두 개 있습니다.

| 버튼 | 실행하는 것 | 특징 |
|---|---|---|
| **대시보드 생성** | `dashboard_recreate.bat` | 한 번 실행하고 끝. 서버 없음. **값을 저장하지 않습니다** — 지금 엑셀에 저장된 내용을 HTML로 다시 뽑아내기만 함 |
| **실시간 입력 서버 시작** | `run_live_server_hidden.vbs`(있으면) 또는 `run_live_server.bat`(예전 버전 대비) | 계속 떠 있는 서버. 브라우저 화면에서 입력/수정/삭제하면 **Windows COM으로 엑셀에 바로 반영**됨 (pywin32 필요). **콘솔 창이 뜨지 않습니다** — 정상 시작되면 브라우저만 자동으로 열리고, 문제가 있을 때만 안내 창이 뜹니다 |

**대시보드 생성** 버튼을 쓸 때는 입력/수정을 여전히 `PPA_통합입력폼`
(`입력폼` 시트) 또는 `PPA_탐색폼`(`탐색` 시트)에서 하고, 이 버튼은 "지금
엑셀에 저장된 내용을 HTML로 다시 뽑아내는" 역할만 합니다.

```
① 데이터 입력/수정  →  입력폼 또는 탐색 시트 (저장까지)
② 대시보드 생성      →  대시보드생성 시트의 [대시보드 생성] 버튼
③ 자동으로 PPA현황.html 이 열리고, [변경] 탭에 ①에서 바뀐 내용이 표시됨
```

**실시간 입력 서버 시작** 버튼을 쓰면, 브라우저 화면에서도 바로 입력·수정·
**삭제**까지 할 수 있습니다 — ①번을 입력폼/탐색 대신 브라우저의 "간편
입력/저장" 창에서 해도 되고, 대시보드의 각 표 탭 안의 "+ 추가" 버튼이나
행을 클릭했을 때 뜨는 상세 화면의 "수정"/"삭제" 버튼으로도 같은 폼이
열립니다. 표가 클 때는 컬럼별 키워드 검색으로 기존 데이터를 바로 찾을 수
있고, "그룹A(발전소+구매계약)"/"그룹B(수요기업+판매계약+전기사용지)"를
고르면 서로 연결된 여러 표를 한 화면에서 한 번에 입력·삭제할 수도 있습니다.
삭제는 다른 표에서 참조 중인 데이터면(그룹 배치 밖에서 참조하는 경우 포함)
자동으로 막아주는 안전장치가 있습니다.

이 버튼을 누르면 이제 **콘솔 창도 안내 창도 뜨지 않고** 몇 초 뒤 브라우저만
자동으로 열립니다(내부적으로 `run_live_server_hidden.vbs`를 씀). 문제가
있을 때만(엑셀/python을 못 찾음, 서버가 응답하지 않음) 안내 창이 뜨고, 그
동안의 서버 출력은 `static-dashboard\live_server.log`에 남습니다. 콘솔을
직접 보고 싶으면 `static-dashboard\run_live_server.bat`을 더블클릭해서
예전 방식으로 실행할 수 있습니다.

자세한 동작(엑셀이 열려 있을 때/아닐 때 차이, pywin32 설치, 동시 저장 처리,
삭제 시 참조 검사, 그룹 일괄 입력, 표 안에서 바로 수정/추가/삭제, 시작 속도/
콘솔 숨김)은 `../static-dashboard/README.md`의 "실시간 입력 서버" 절을 꼭
먼저 읽어주세요 — 이 문서는 엑셀 쪽 버튼만 다룹니다.

## 왜 필요한가 — "누적되지 않고 초기화된다"는 문제

`build_dashboard.py`는 실행할 때마다 그 시점 데이터를 `PPA현황_snapshot.json`에
저장해두고, 다음 실행 때 그 파일과 비교해서 [변경] 탭을 채웁니다. 이 비교가
계속 이어지려면 **매번 같은 폴더에서, 같은 출력 파일명으로** 실행돼야 합니다 —
더블클릭 위치가 매번 달라지거나 출력 파일명이 바뀌면 스냅샷을 못 찾아 매번
"첫 실행"처럼 리셋된 것처럼 보입니다.

이번에 새로 만든 `dashboard_recreate.bat`은 **자기 자신이 있는 폴더 기준으로만**
동작하고 출력 파일명(`PPA현황.html`)도 고정해뒀습니다. 이 버튼으로 실행하면
그 `.bat`을 그대로 호출하므로 항상 같은 스냅샷과 비교됩니다. 실행할 때마다
화면에 "비교 대상 스냅샷: … 있음/없음"이 표시되니, 매번 같은 파일을 보고 있는지
직접 확인할 수 있습니다.

## 폴더 구조 (중요)

두 버튼 모두 통합문서 바로 옆에 `static-dashboard` 폴더가 있다고 가정합니다.

```
📁 (작업 폴더)\
   PPA파일.xlsm              ← 이 통합문서 (입력폼·탐색·대시보드생성 매크로 포함)
   📁 static-dashboard\
      dashboard_recreate.bat  ← [대시보드 생성] 버튼이 실행
      run_live_server.bat     ← [실시간 입력 서버 시작] 버튼이 실행
      build_dashboard.py, excel_com.py, ppa_liveserver.py,
      dashboard_form.js, ppa_*.py, vendor\...
      PPA현황.html            ← 생성 결과 (자동으로 열림)
      PPA현황_snapshot.json   ← 자동 갱신 - 지우지 마세요
   📁 python-embed\           ← python 미설치 환경만 필요
```

xlsm이 OneDrive 동기화 폴더 안에 있으면 `.bat`이 실행 중 참고 메시지를 띄웁니다
(동기화가 덜 됐거나 다른 프로그램이 파일을 열어둔 상태면 오류가 날 수 있음 —
`static-dashboard/README.md`의 기존 안내대로 로컬 사본 사용을 권장).

## 설치

1. 원본 xlsm의 **사본**에서 먼저 시험하세요.
2. GitHub에서 **Code → Download ZIP**으로 받습니다(Raw 우클릭 저장은 UTF-8이라
   한글이 깨집니다 — 다른 두 모듈과 동일한 주의사항).
3. `static-dashboard` 폴더 전체를 xlsm과 같은 폴더에 둡니다(위 구조대로).
4. 엑셀에서 `Alt`+`F11` → **파일 → 파일 가져오기** → `PPA_대시보드생성.bas` 선택
5. 왼쪽 목록에 `PPA_DashboardGen` 모듈이 한글 깨짐 없이 들어왔는지 확인
   (깨졌다면 `README.md`의 "이미 오류가 났다면" 절차 참고 — 세 모듈 모두 동일)
6. VBE를 닫고 `Alt`+`F8` → **대시보드_만들기** → 실행
7. `대시보드생성` 시트가 생기고 버튼이 놓입니다. 이후로는 버튼만 쓰면 됩니다.

`입력폼`(PPA_InputForm), `탐색`(PPA_Explorer)과 **완전히 독립적으로 동작**합니다.
셋 다 가져와도 되고, 필요한 것만 가져와도 됩니다.

## 버튼을 누르면 일어나는 일

1. 저장 안 한 변경사항이 있으면 저장할지 먼저 물어봅니다(대시보드는 디스크에
   저장된 내용만 읽으므로, 저장 안 하면 방금 입력한 내용이 안 잡힙니다).
2. `static-dashboard\dashboard_recreate.bat`을 **이 통합문서의 정확한 경로**를
   인자로 넘겨 실행합니다 — 어떤 xlsm을 읽을지 추측할 필요가 없습니다.
3. 배치파일이 끝날 때까지 엑셀이 기다립니다(진행 상황이 검은 창에 그대로
   보입니다). 시트의 "상태" 칸도 같이 갱신됩니다.
4. 성공하면 `PPA현황.html`이 자동으로 열립니다.

## [실시간 입력 서버 시작] 버튼을 누르면 일어나는 일

1. **저장 여부를 묻지 않습니다** — [대시보드 생성]과 달리, 이 서버는 지금
   화면(메모리) 상태를 Windows COM으로 직접 읽어가므로 저장 안 한 내용도
   반영됩니다.
2. `static-dashboard\run_live_server.bat`을 **이 통합문서의 정확한 경로**를
   인자로 넘겨 실행합니다 — **끝날 때까지 기다리지 않고 바로 돌아옵니다**
   (서버는 계속 떠 있어야 하므로 [대시보드 생성]처럼 동기 실행하면 안 됨).
3. 새로 뜬 검은 콘솔 창이 서버 본체입니다. 몇 초 안에 브라우저가 자동으로
   열리고, 대시보드 화면 오른쪽 아래에 "간편 입력/저장" 버튼이 보입니다.
4. 그 창을 닫으면 서버도 함께 종료됩니다. pywin32가 설치돼 있지 않으면
   그 창에 안내가 뜨고 바로 멈춥니다(`static-dashboard/README.md`의
   'pywin32 설치' 절차 참고).
5. 브라우저에서 저장을 누르면 실제 엑셀에 반영됩니다 — 지금 이 통합문서가
   열려 있는 상태라면, 저장을 누르는 순간 화면의 셀 값이 바뀌는 것을 직접
   볼 수 있습니다.

## 회사 보안 정책으로 매크로의 외부 프로그램 실행이 막혀 있다면

일부 VDI는 매크로가 `Shell`/`WScript.Shell`로 다른 프로그램을 실행하는 것을
막아둡니다. 이 경우 버튼을 눌러도 "배치파일을 실행하지 못했습니다" 오류가
납니다 — 그러면 `static-dashboard` 폴더에서 해당 `.bat`(`dashboard_recreate.bat`
또는 `run_live_server.bat`)을 **직접 더블클릭**해서 실행하면 됩니다(버튼과
결과는 동일, 자동 연결만 없을 뿐).

## "클라우드 경로" 오류가 뜬다면 (OneDrive/SharePoint)

엑셀의 자동 저장(AutoSave)이 켜진 채로 OneDrive/SharePoint에서 이 통합문서를
열면, 엑셀이 파일 위치를 `C:\...` 같은 로컬 경로가 아니라 `https://...` 클라우드
주소로 인식합니다. 그 상태로는 배치파일이 있는 로컬 폴더를 찾을 방법이 없어서
두 버튼 모두 막힙니다.

버튼을 누르면 자동으로 다음 순서로 시도합니다:

1. `ThisWorkbook.FullName`이 로컬 경로(`C:\...`)면 바로 진행합니다.
2. **클라우드 경로(`https://...`)면, 이 컴퓨터의 OneDrive 로컬 동기화 폴더
   전체를 뒤져서 같은 이름의 파일을 자동으로 찾습니다**(`Environ$`의
   `OneDrive`로 시작하는 환경변수들이 가리키는 폴더 밑에서 `dir /s /b`로
   검색). 찾으면 그 위치를 그대로 씁니다 — 사용자가 자동 저장을 끄거나
   파일을 다시 열 필요 없이 그냥 넘어갑니다. 파일이 아주 많은 팀 사이트라면
   검색에 시간이 좀 걸릴 수 있습니다(진행 중엔 시트의 "상태" 칸에 표시).
3. 그래도 못 찾으면 그때 안내창이 뜨고, 아래 두 가지를 시도해볼 수 있습니다:
   - **파일 → 정보**에서 이 파일의 자동 저장(AutoSave)을 끄고 다시 시도
   - OneDrive 앱에서 이 파일이 있는 폴더까지 동기화가 끝났는지 확인
   - 그래도 안 되면, 조직 정책으로 이 SharePoint 문서함이 로컬 경로 노출 자체를
     막아뒀을 수 있습니다 — 이 경우는 매크로 쪽에서 우회할 방법이 없고,
     IT 담당자에게 문의하거나 팀이 접근 가능한 다른 위치(사내 파일 서버 등)로
     옮기는 방법을 검토해야 합니다.

이 경우가 아닌 다른 원인으로 여전히 오류가 나면, **"대시보드 생성 - 오류"**
라는 창이 뜨면서 어느 단계·`Err.Number`·설명까지 보여줍니다. 그 창을 그대로
캡처해서 보내주시면 바로 원인을 잡을 수 있습니다.

## ⚠️ 파일 인코딩 주의

다른 두 모듈과 동일합니다 — `.bas`는 ANSI(CP949)로 저장돼 있어야 VBE 가져오기에서
한글이 안 깨집니다. 자세한 원인과 "허가된 개체 이름이 아닙니다" 오류 대처법은
`README.md`를 참고하세요.

## 확인된 범위 / 먼저 봐주실 것

정적 점검(프로시저 정의·호출 인자 수·블록 짝·중복 선언·`Option Explicit` 위반)은
통과했지만, **이 환경에는 엑셀이 없어 실제로 실행해보지 못했습니다.** 사본에서
아래 순서로 확인해주세요.

1. `대시보드_만들기` 실행 → `대시보드생성` 시트와 버튼이 생기는지
2. 버튼 클릭 → 검은 창(배치파일)이 뜨고 "대상 엑셀 파일"에 지금 이 통합문서의
   경로가 정확히 나오는지
3. 완료 후 `PPA현황.html`이 자동으로 열리고, 시트의 "상태" 칸에 성공 시각이
   찍히는지
4. 아무 셀 하나를 고치고 저장 → 버튼을 다시 누르기 → 새로 열린 HTML의 [변경]
   탭에 그 항목이 "수정"으로 뜨는지 (누적 문제가 실제로 고쳐졌는지 확인하는
   핵심 단계)
5. `static-dashboard` 폴더가 없거나 이름이 다를 때 → 버튼을 누르면 정확한
   위치를 알려주며 멈추는지(조용히 실패하지 않는지)
6. [실시간 입력 서버 시작] 버튼 → 검은 콘솔 창이 뜨고 몇 초 안에 돌아오는지
   (배치파일이 끝날 때까지 엑셀이 멈춰 있지 않아야 함 — 대시보드 생성과
   달리 비동기 실행). 이후 동작(엑셀 반영, pywin32 미설치 시 안내 등)의
   자세한 확인 항목은 `../static-dashboard/README.md`의 "확인된 범위" 절을
   참고해주세요.
7. **클라우드 경로 자동 검색**(신규): SharePoint 라이브러리에 있어 AutoSave를
   꺼도 계속 `https://...` 경로로 열리는 파일에서 버튼을 눌러보고, OneDrive
   로컬 동기화 폴더에서 자동으로 찾아서 정상 진행되는지 확인해주세요. 조직
   정책으로 이런 상태가 자주 생긴다면 특히 중요한 확인 항목입니다.

걸리는 게 있으면 화면을 캡처해 보내주세요.
